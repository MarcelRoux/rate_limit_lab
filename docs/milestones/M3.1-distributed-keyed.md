# Milestone M3.1 — Distributed Keyed Limiting

## Goal

Delegate per-key rate-limiting state to a backend so that distributed enforcement can run with the same decision model. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: DistributedKeyedLimiter; crates/state_backend/src/redis_backend/scripts.rs: FIXED_WINDOW_LUA)

## Implemented Components

- `crate: state_backend`
  - `StateBackend` trait, `BackendDecision`, and `LimitSpec` for fixed-window enforcement. (crates/state_backend/src/backend.rs: StateBackend, BackendDecision, LimitSpec)
  - `RedisBackend` plus `FIXED_WINDOW_LUA` script that atomically increments counters and returns delay hints. (crates/state_backend/src/redis_backend/backend.rs: RedisBackend; crates/state_backend/src/redis_backend/scripts.rs: FIXED_WINDOW_LUA)
- `crate: rate_limit_distributed`
  - `DistributedKeyedLimiter` that owns a backend `Arc`, namespace, and limit spec while exposing an async `check`. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: DistributedKeyedLimiter)

## Decision Semantics

- `DistributedKeyedLimiter::check` calls `StateBackend::check(namespace, key, limit)` and maps `BackendDecision::Allow` and `BackendDecision::Deny` directly to `Decision` outcomes. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: DistributedKeyedLimiter::check; crates/state_backend/src/backend.rs: BackendDecision)
- Backend fault paths currently produce `Decision::Deny` with a fixed 50 ms retry duration. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: BACKEND_ERROR_RETRY_AFTER; DistributedKeyedLimiter::check)
- Namespacing is applied at the limiter boundary so independent experiments do not share counters. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: DistributedKeyedLimiter::new)
- Redis backend uses a fixed window, allowing count resets on expiration and returning `PTTL` as `retry_after` on deny. (crates/state_backend/src/redis_backend/scripts.rs: FIXED_WINDOW_LUA)

## Failure Behavior

- Backend errors currently translate into deny decisions with `retry_after = 50 ms`, which may reduce availability but keeps behavior deterministic. (crates/rate_limit_distributed/src/distributed_keyed_limiter.rs: BACKEND_ERROR_RETRY_AFTER; DistributedKeyedLimiter::check)
- Redis backend reports `BackendError::InvalidResponse` when the Lua script returns an unexpected shape. (crates/state_backend/src/redis_backend/backend.rs: RedisBackend::check; crates/state_backend/src/error.rs: BackendError)

## Out of Scope

- Hybrid local + distributed compositions (M3.2). (crates/rate_limit_hybrid/src/lib.rs: module doc comment)
- Failure policy experimentation beyond the placeholder deny-on-error behavior. (docs/adr/ADR-0004-distributed-failure-policy.md)
