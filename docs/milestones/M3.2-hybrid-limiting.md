# Milestone M3.2 — Hybrid Local + Global Limiting

## Status

Completed (2026-02-17)

## Goal

Implement a hybrid limiter that composes:

- a local in-memory limiter (rate_limit crate)
- a distributed per-key limiter backed by a StateBackend (rate_limit_distributed crate)

The hybrid limiter must enforce **Strict AND** semantics:

- Allow only if both local and distributed checks allow
- Deny otherwise
- Retry-After is the **maximum** retry-after observed across the components that deny

## Existing Implementations (Reference)

- `HierarchicalLimiter<K,S>`: local global + local per-key AND semantics, sync.
  - Deny retry_after = max(retry_after_global, retry_after_per_key)
- `DistributedKeyedLimiter<K,B,S>`: async per-key check via backend.
  - Current backend error policy placeholder: maps backend errors to Deny with 50ms retry

## Proposed M3.2 Hybrid Semantics

### Decision composition

- Decision = AND(local_decision, distributed_decision)
- If either denies, hybrid denies.
- retry_after:
  - If both deny: max(local.retry_after, distributed.retry_after)
  - If one denies: that retry_after
  - Else allow

### Ordering (Option A2: Parallel)

- Start distributed check future **immediately** (head start)
- Perform local check immediately (sync)
- If local denies:
  - return deny immediately (do not await distributed result)
- Else:
  - await distributed decision and combine

This gives low-latency denies when local fails, and reduces latency when local passes.

### Failure policy toggle for backend errors

Add a configurable policy for when the distributed backend check errors:

- FailOpen: treat backend error as Allow (availability-first)
- FailClosed: treat backend error as Deny with short retry_after (correctness-first)
Default: **FailOpen** (supports failure-injection experiments without taking the service down)

This policy must be:

- documented (ADR)
- observable (metrics/events)
- testable deterministically

## Non-goals (M3.2)

- Reconciliation / reservation semantics
- Distributed budget caching
- Advanced failure policies (adaptive circuit breaking)
- Any new backend implementation
- State consolidation via lease allocation + refresh loop (deferred to M3.5; see docs/backlog/0002_hybrid_limiter_backend_outage_semantics.md and docs/backlog/0004_distributed_keyed_limiter_revision.md)

## Acceptance Criteria

- [x] A new hybrid limiter exists as a separate crate (or module) that composes local + distributed.
- [x] Strict AND semantics implemented with Option A2 ordering.
- [x] Configurable distributed backend failure policy (default fail-open).
- [x] Tests cover decision semantics including local deny short-circuit, distributed deny, both deny (retry_after max), and distributed backend error with fail-open and fail-closed.
- [x] Documentation includes ADR for semantics ordering and ADR for failure policy toggle/default rationale.
- [x] REST adapter can select hybrid limiter via feature + config (minimal wiring).
